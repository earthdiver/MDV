# 使い方と設定

[English](portable.en.md)

## 配布版とエンジン

「ヘルプ → MDVについて」とウィンドウのタイトルで使用中の版を確認できます。両エンジン同梱版では「表示 → 公開実装エンジンを使用」で切り替えます。独自エンジン版と公開実装利用版では方式が固定されます。どの版でもGitHub／Qiitaの記法を選べます。

## 文書を開く・読む

「開く」「最近開いたファイル」、ドラッグ＆ドロップから文書を開けます。複数ファイルにも対応し、開いている文書はタブで切り替えます。同じファイルをもう一度開くと、そのタブを選択します。

- **目次**：見出しを選ぶと、その位置へ移動します。
- **ソースを表示**：Markdownの原文を読み取り専用で表示します。
- **文書内を検索**：本文やコード内の文字を検索します。図や数式、装飾の境界をまたぐ語は検索できない場合があります。
- **再読み込み**：外部エディターで保存した変更は自動反映されます。WSL（`\\wsl.localhost\…`、`\\wsl$\…`）などの共有パスでは、表示中の文書を約2秒間隔で確認します。手動でも再読み込みできます。
- **印刷・保存**：「ファイル → 印刷」「ファイル → PDFに保存」を使います。PDF（Portable Document Format）は、文書の配置を保って共有するためのファイル形式です。
- **見た目**：「表示」から目次、ソース、ダークテーマ、表示倍率を変更できます。

タブごとに、GitHub／Qiitaの選択、表示倍率、検索語、閲覧位置、折りたたみ状態を保持します。タブと閲覧履歴は終了すると失われ、次回起動時には復元されません。タブの「×」または中央クリックで閉じられ、最後のタブを閉じると空のタブが残ります。

文書内のMarkdownリンクは同じタブで開きます。Ctrlを押しながらクリックするか中央クリックすると、別のタブで開きます。「戻る」「進む」で文書と閲覧位置を戻せます。戻った先で別の文書へ移動すると、その先の履歴は置き換わります。

## 表示言語

初期設定の「自動（システム設定）」では、Windowsの表示言語が日本語なら日本語、それ以外なら英語を使います。「言語 → 日本語／English」で明示的に選択でき、変更はすぐに反映されます。文書本文は翻訳しません。「ヘルプ → サンプルを開く」は選択した言語のサンプルを開きます。

選択はEXEと同じ場所のINIに即時保存し、再起動後も維持します。再びWindowsに合わせる場合は「自動（システム設定）」を選びます。INIの `[Viewer]` セクションには `Language=auto`、`Language=ja`、`Language=en` のいずれかを保存します。未指定や無効な値は自動選択になります。INIを直接編集する場合はアプリを終了してください。

GitHubモードのHTML文字色（`font color`、`style="color:…"`）はGitHub本家と同様に除去します。Qiitaの`font color`は維持します。Mermaidは2026年10月14日の本家配信版に合わせ、GitHubは12.1.0、Qiitaは11.12.1を同梱しています。これはupstream/custom共通です。GitHub本家でmindmapのSVG描画も確認しています。公開Markdown変換ライブラリだけでは実サイトのタグ除去や図の描画は再現されないため、MDVの表示段階で調整しています。

## 画像とリンク

外部画像は初期状態では読み込みません。「表示 → 外部画像を読み込む」を有効にすると、画像の配信先へ通信します。文書本文を外部の変換サービスへ送信することはありません。Webページやメールのリンクは、クリック時に既定のアプリで開きます。

両モードとも「表示 → GitHubの画像／Qiitaの画像 → 画像を取得・保存…」から、文書内のHTTP／HTTPS画像を取得してオフライン用に保存できます。通常は記事・文書URLの入力は不要です。Markdownに書かれた画像URLから直接取得し、ローカルに存在する画像はそのまま使用します。ローカル画像も一緒に持ち運んでください。

保存画面には、次の任意の取得方法があります。初期状態ではどちらもOFFです。

| モード | 任意の項目 | URLが必要な用途 |
| --- | --- | --- |
| GitHub | GitHubから相対パス画像も取得 | ローカルに存在しない相対パス画像を、指定したGitHub文書を基準に取得 |
| Qiita | Qiita本家のCDN画像を取得 | 公開記事にある署名付きCDN画像を、文書の画像URLと照合して取得 |

GitHubの項目を選ぶ場合は公開文書のblob URLまたはraw URLを入力します。相対パスは文書の位置を基準に、`/`から始まるパスはリポジトリのルートを基準に解決し、`../images/a.png`もリポジトリ内なら取得できます。この追加取得先はGitHubのraw画像に限ります。認証が必要な非公開リポジトリは対象外です。ブランチ名に`/`を含む場合はコミットSHAを指定してください。通常の絶対URL画像は、この項目を選ばなくても保存できます。

Qiitaの項目を選ぶ場合は公開記事URLを入力します。一致する画像には本家の標準解像度（`srcset`の`1x`、なければ`src`）を使い、一致しない外部画像はMarkdown内の元URLから保存します。通常の保存ではS3などの元画像をそのまま取得するため、CDNによる縮小・変換は適用しません。表示サイズは本文幅・倍率・画像の幅／高さ指定にも左右され、Qiitaとの完全一致は保証しません。

保存結果には、保存数、既存ローカル画像数、未取得数と、未取得の画像URL／パス・理由を表示します。一部の画像を取得できなくても、取得できた画像で保存データを更新します。その場合、それ以前の保存データは今回取得できた画像で置き換わります。1枚も保存できない場合、保存処理全体の失敗・キャンセル時は、以前の保存データと表示設定を維持します。保存に成功すると「保存した画像を使用」をONにします。

保存後は両エンジンでオフライン表示できます。GitHubでは「保存した画像を使用」と「外部画像を読み込む」が排他的で、どちらかをONにすると、もう一方はOFFになります。Qiitaでは「保存した画像を使用」「外部画像を読み込む」「CDNから直接表示」のいずれかをONにすると、ほかの2つはOFFになります。すべてOFFにもできます。ローカル画像は引き続き表示します。保存画像を選んだ場合、対応する保存画像のない外部画像は表示しません。原画像をオンライン表示するには「外部画像を読み込む」をONにしてください。選択した取得先で画像の読み込みに失敗しても、別の取得先へ自動では切り替わりません。

Qiitaの「CDNから直接表示…」は、保存せずに公開記事の画像をオンライン表示する機能です。この機能には記事URLの指定が必要です。記事URLの取得に成功した時点で表示方法を切り替え、失敗・キャンセル時は以前の選択を維持します。一致するCDN画像だけを取得し、一致しない外部画像は表示しません。チェックを外すと解除できます。

画像の取得方法は文書・表示モードごとにアプリ終了まで保持し、タブ切替・履歴移動・再読み込みでも維持します。

`example.md`の画像の保存先は、Markdownの隣の`example.md.mdv-github-images.zip`または`example.md.mdv-qiita-images.zip`です。元のMarkdownは変更しません。文書を移すときはZIPも一緒に移し、文書名を変える場合はZIPの文書名部分も合わせてください。上限は1文書128画像・合計256 MiB・1画像32 MiBです。

保存内容は取得時点の画像です。文書を開く・再読み込み・モード切替では保存データを自動取得しません。更新には再度「画像を取得・保存…」を実行し、削除には「この文書の保存画像を削除」を使います。GitHubとQiitaの保存データ・保存画像設定は独立しています。

文書内から参照するローカル画像とMarkdownは、開いた文書と同じフォルダか、その下のフォルダに置いてください。親フォルダへの参照や、別の場所へのリンクとして作られたフォルダ・ファイル（ジャンクション、シンボリックリンク）には対応しません。

例えば `notes/readme.md` を開いている場合、`images/photo.png` は `notes/images/photo.png` を参照できます。`../photo.png` のように `notes` の外を参照するリンクは開けません。ドライブ名から始まるパスや共有フォルダへの直接リンクも対象外です。

## Qiitaリンクカードの保存

通常はオフライン用のURLカードを表示します。本家のタイトル・サムネイルを使う場合は、Qiitaモードで「表示 → Qiitaリンクカード → オンラインで取得・保存」を選び、「取得して保存」を押します。この操作だけがQiitaの公開OGP取得先とサムネイル配信先に通信します。単独URLから生成したカードだけを対象にし、通常の本文リンクは取得しません。

保存後は両エンジンでオフライン表示できます。「保存したリンクカードを使用」を外すとURLカードに戻ります。文書を開く・再読み込みする・モードを切り替える操作では通信せず、更新は再度「取得・保存」を実行します。取得失敗・キャンセル時は以前の保存内容を保持します。「この文書の保存カードを削除」で削除できます。

保存先はMarkdownの隣の `example.md.mdv-qiita-cards.zip` です。文書の移動・改名時は保存ファイルも合わせてください。上限は128カード・サムネイル合計256 MiB・1画像32 MiBです。保存した内容は取得時点のものです。画像の保存設定とは独立しています。

## 設定の保存・移行

設定ファイルは、実行ファイルと同じフォルダに同名の `.ini` として作られます。以下では、実行ファイル名を `MDV.exe`、設定ファイル名を `MDV.ini` とした例を示します。表示言語、表示方式、テーマ、表示倍率、目次・ソースの設定、最近開いたファイルを保存します。通常はアプリのメニューから変更してください。

- **別の場所へ移す**：アプリを終了し、`MDV.exe` と `MDV.ini` を一緒に移します。
- **名前を変える**：`Reader.exe` に変更した場合は、設定ファイルも `Reader.ini` に変えます。
- **設定を初期化する**：アプリを終了し、設定ファイルを削除します。

最近開いたファイルの場所は自動で変更されません。文書を移動した場合は「開く」から選び直してください。設定を保存できない場合は、実行ファイルのあるフォルダに書き込めるか、設定ファイルが読み取り専用になっていないか確認してください。

設定保存やファイルの関連付け登録に、Windowsのレジストリは使いません。ただし、Windows自体が記録する実行履歴などを消去する機能はありません。

## 更新と一時ファイル

更新するときは、起動中のすべてのMDVを終了してからEXEを置き換え、設定ファイルを残します。EXEの配布名に含まれるバージョンや版を変える場合は、設定ファイルも新しいEXEと同じ名前の `.ini` に改名してください。毎回EXEを `MDV.exe` に改名して使えば、`MDV.ini` をそのまま引き継げます。本文表示に使うWebView2も内蔵しており、MDVの配布ファイルを更新することで入れ替わります。

起動時に必要なファイルをWindowsの一時フォルダへ展開します。初回起動は時間がかかるため、**一時フォルダに1 GB以上の空き容量**を用意してください。複数の版を使うと、その分の展開ファイルが残ります。

表示に失敗する場合や一時ファイルを整理する場合は、すべてのMDVを終了してから、エクスプローラーのアドレスバーに `%TEMP%`（Windowsの一時フォルダ）を入力し、次の場所を削除できます。

| 場所 | 内容 |
| --- | --- |
| `MDV` フォルダ | 展開した資材と作業データ |
| `.net` 内のMDVの実行ファイル名に対応するフォルダ | 実行に必要な展開ファイル。他のアプリのフォルダは残してください |

次回起動時に必要なファイルを作り直します。設定ファイルや元のMarkdown文書は、この操作では削除されません。
